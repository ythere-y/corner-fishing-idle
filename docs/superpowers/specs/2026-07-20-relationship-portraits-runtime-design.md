# 河湾人物头像运行时接入设计

## 状态

- 日期：2026-07-20
- 设计结论：采用方案 B「分层使用」
- 范围：只改变河湾人情 UI 的人物呈现，不改变好感、到访、委托、Buff、终章或存档规则

## 目标

让 `assets/art/character/npc/` 中五张 1254×1254 RGBA 人物图真正进入运行时，并按界面层级使用不同构图：HUD 快速识别、人情簿建立人物记忆、到访面板突出动作和性格。

## 资源真值

在 `relationship_data.gd` 的每位 NPC 定义中增加运行时头像路径，分别指向：

- `lin_aunt.png`
- `zhou_uncle.png`
- `tang.png`
- `xiaoman.png`
- `ma.png`

UI 不自行拼路径。资源不存在或加载失败时，统一回退到现有主题色圆形占位，不产生空白按钮或脚本错误。

## 三层呈现

### 右侧到访入口

- 维持现有约 40–48 px 圆形按钮和最多五人的纵向排列。
- 人物图置于圆形裁切容器，使用等比缩放，不拉伸。
- 保留人物主题色作为 2–3 px 外圈，继续承担身份和状态辨识。
- 来意类型继续用现有文字或角标表达，不通过给头像整体染色来表达，避免污染水彩颜色。
- Tooltip 保留人物名与来意类型。

### 人情簿人物列表

- 每位人物条目左侧增加约 64–80 px 的半身／动作缩略图。
- 图片使用透明背景，不增加白色方形底；卡片原有纸张背景透出。
- 姓名、关系等级、偏好、当前到访和终章状态仍在右侧稳定文本区。
- 五人列表保持相同文字起始线，人物轮廓不得挤压或覆盖文本。

### 单人到访面板

- 面板顶部使用双栏构图：左侧透明人物图，右侧为人物名、来意、剧情或说明。
- 人物图显示约 120–160 px，使用完整透明轮廓，允许脚部或动作边缘在人物区内自然留白。
- 人物区不得侵入下方鱼篓、送礼、交付、领取 Buff 等操作区域。
- 小尺寸窗口下允许人物图缩小，但不能把文字压成过窄列；必要时退化为上方横排头像加下方全文。

## 组件边界

新增一个集中式人物图构建辅助函数，输入 NPC 数据、显示尺寸和展示模式，输出安全的 `TextureRect`／容器：

- `circle`：HUD 圆形裁切。
- `card`：人情簿缩略图。
- `hero`：到访面板透明立绘。

辅助函数负责资源加载、等比模式、最小尺寸和失败回退。调用处不重复资源判断与裁切参数。

## 验证

自动验证至少覆盖：

- 五位 NPC 均配置有效资源路径。
- 五张图片均可加载为纹理。
- 缺失路径走回退逻辑，不返回空节点。
- 人情逻辑回归保持 0 失败。

视觉验证通过 `tools/dev_screenshot.gd` 至少输出：

- 三位以上 NPC 同时到访时的右侧头像栏。
- 五人完整人情簿。
- 一张普通到访面板。
- 一张带鱼篓交付区的委托或终章面板。

验收标准：头像可辨认、不变形、不遮字、不覆盖操作区；五人主题色仍可见；缺图时界面可用。

## 非目标

- 不重绘或编辑现有人物 PNG。
- 不加入立绘动画、眨眼、口型或语音。
- 不替换底部“人情”系统图标。
- 不改变人物事件文本和玩法数值。
