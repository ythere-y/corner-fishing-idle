# 人情到访会话状态与单行气泡设计

日期：2026-07-21  
状态：Owner 已确认  
范围：河湾人情到访页面、到访临时状态与对应回归测试

## 目标

1. 修复切换或重新打开到访时，偶发继承上一次反馈、拒收提示或鱼篓展开状态的问题。
2. 到访采用方案 B：NPC 使用左侧头像气泡，玩家可选回复直接表现为右侧可点击气泡。
3. 每条消息和每个回复选项独占一整行布局槽位，双方内容不得在 Y 轴重叠。

## 根因

当前 `selected_relationship_visit_id`、`relationship_visit_feedback`、
`relationship_visit_notice` 与 `relationship_picker_open` 分散存放在主节点上。
只有右侧头像入口 `_open_relationship_visit()` 会完整清理临时字段；测试面板的召唤与打开入口、
普通关闭以及部分面板重建路径可以绕过这一入口。临时状态没有绑定所属 NPC 或事件，
因此旧值可能被新到访错误读取。

## 会话状态

将到访临时字段收敛为一个当前会话对象。会话至少包含：

- `npc_id`：当前 NPC。
- `visit_key`：由 NPC、事件类型、创建时间或人物事件等级组成的稳定标识。
- `phase`：`decision`、`picker` 或 `feedback`。
- `player_reply`：已经选择并需要显示的玩家回复；未选择时为空。
- `notice`：当前会话中的拒收或鱼已不存在提示。
- `feedback`：NPC 对本次选择的反馈及语气。

会话不写入存档，不保存跨到访聊天历史。

### 生命周期

- **开始**：所有入口统一调用开始会话。若 NPC 或 `visit_key` 与当前会话不同，先清空旧会话再建立新会话。
- **重绘**：同一会话因选择回复、打开鱼篓或刷新面板而重绘时，保留当前会话。
- **选择**：记录玩家回复，然后进入 `picker` 或 `feedback`；不允许旧会话的字段参与结算。
- **结束**：关闭面板、结束反馈、到访消失或切换 NPC 时统一销毁会话。
- **兼容入口**：右侧头像、测试面板召唤、测试面板打开均走同一开始函数，不再直接设置选中 NPC 后打开面板。

若当前会话与真实到访不匹配，UI 不渲染旧消息，并安全建立新会话或显示人物已离开。

## 气泡布局

页面保留紧凑人物标题，但主要内容改为纵向消息流。

### NPC 消息

- 每条 NPC 消息使用一个全宽消息行。
- 行内从左到右为 32–40 px 圆形头部头像、间距、浅色水彩纸气泡、右侧弹性留白。
- 气泡显示第一人称内容，不在正文重复“林阿姨：”等姓名前缀。
- 连续 NPC 消息仍各占一行，头像可以每行显示，以保持实现与识别稳定。

### 玩家回复

- 每个可选回复独占一个全宽消息行。
- 行内先放左侧弹性留白，再放右对齐的可点击玩家气泡。
- 主选项使用偏暖绿色或现有金色强调；次选项使用深色描边，但两者均保持聊天气泡轮廓。
- 点击后，未选项消失；所选回复保留为普通右侧气泡，不再表现为按钮。
- NPC 反馈在其后的下一条全宽行出现，不能与玩家消息共享同一 `HBoxContainer`。

### 鱼篓选择

- “我挑一条。”或“给你看看。”仍是右侧回复气泡。
- 选择后进入 `picker` 阶段，鱼篓作为消息流下方的独立操作区出现。
- “先收起来。”和“我再想想。”使用独立右侧回复行；收起仅返回当前会话决策阶段，关闭则结束会话。

### 防重叠约束

- 消息流根节点使用纵向容器。
- 每条消息或选项必须创建独立行容器，并由最小尺寸与自动换行决定高度。
- 不通过 `position`、负间距或覆盖式锚点排列消息。
- 长文本换行只增加本行高度，后续行由容器自动下移。

## 反馈流程

1. NPC 左侧气泡提出当前事件。
2. 玩家看到若干右侧可点击回复气泡。
3. 玩家点击后，页面重绘为 NPC 原消息、玩家已发送气泡、NPC 新反馈。
4. 反馈完成后只显示结束本次到访的操作。

不增加逐字动画、跨次聊天记录、输入框或自由文本回复。

## 验证

自动回归至少覆盖：

- NPC A 留下反馈后直接打开 NPC B，B 不显示 A 的反馈。
- 拒收提示、鱼篓展开态、已选玩家回复均不能跨 NPC 或跨事件继承。
- 普通关闭后重新打开同一到访，从干净的决策阶段开始。
- 测试面板召唤和打开与右侧头像入口具有相同的会话初始化行为。
- NPC 消息行包含圆形头像和气泡。
- 每个玩家回复属于独立的全宽消息行，且不与 NPC 行复用容器。
- 选择后仅保留所选玩家气泡，NPC 反馈出现在后续独立行。

视觉验证使用 `tools/dev_screenshot.gd`，至少检查人物事件、Buff、鱼篓选择与反馈四种状态；
逻辑验证使用 `godot --headless -s tools/validate_game.gd`，结果必须为 0 失败。
