# 旅行地图底图 `assets/art/ui/world_map.png`

> 真值来源：本文件。换图前先读完「硬约束」与「纠偏」两节，否则十个站点的灯会落进海里。

## 硬约束（代码依赖，非美术偏好）

`world_map.gd::_draw_map_tex()` 把这张图当作**标准全球等距圆柱图**（plate carrée）消费：

| 项 | 要求 |
|---|---|
| 投影 | 等距圆柱 / plate carrée，经纬度 → 像素为线性映射 |
| 覆盖 | 经度 −180°…+180°，纬度 +90°…−90°，**满幅、无留白、无边框** |
| 宽高比 | **严格 2:1**（当前 1774×887）。偏离 2:1 超过 0.15 会被视为「已按视窗裁好」，整图铺满，海岸线将不再与站点经纬度对齐 |
| 光影 | **禁止任何烘焙光影**（昼夜、太阳光晕、投影、暗角）。游戏在其上叠自己的实时晨昏线，两套光源会打架 |
| 文字 | 禁止文字、数字、国界、经纬网、指北针、图例、水印 |

代码只截取 `LON0..LON1 = −35°…180°`、`LAT0..LAT1 = 72°…−50°` 那一块（旅程覆盖的半个地球），
其余部分（美洲、南极）永远不会显示——但**必须存在**，否则线性映射的比例就错了。

## 来历与纠偏（2026-07-08）

当前这张图由 GPT 依 `docs/` 里的美术方向生成（水彩、冷压纸、去饱和、暖沙陆地 + 淡青灰海）。

**原图的坐标是错的**：经度准确（各地标误差 < 1°），但**纬度整体偏南且随纬度线性放大**。
用五块孤立陆地的像素重心做最小二乘拟合（真实纬度 → 图上纬度）：

| 陆地 | 真实纬度 | 原图纬度 | 偏差 |
|---|---|---|---|
| 冰岛 | 64.9 | 62.0 | −2.9 |
| 不列颠 | 54.0 | 51.8 | −2.2 |
| 婆罗洲 | 0.8 | −5.2 | −6.0 |
| 马达加斯加 | −19.4 | −27.7 | −8.3 |
| 新西兰南岛 | −44.0 | −51.2 | −7.2 |

拟合结果：

```
图上纬度 ≈ 1.05286 × 真实纬度 − 5.9152
```

即整张图**南移约 5.9° 并纵向拉伸 5.3%**。据此做一次纯垂直重采样纠正（像素形式）：

```
src_y = 5.707 + 1.05286 × dest_y      # dest_y ∈ [0, 836] 有源数据
dest_y ∈ [837, 886]                   # 越过源图底边，填陆地米色（南极内陆，永不入镜）
```

纠偏后复验：把 `world_map.gd::LAND_POLYS`（位置正确的简笔轮廓）与十个站点坐标叠回图上，
非洲南端、马达加斯加、澳大利亚、新西兰、婆罗洲、菲律宾全部贴合，十盏灯各归其位。

**换新图时**：先做同样的复验（叠 `LAND_POLYS` + 站点点位），确认无需纠偏再入库。
AI 生成的世界地图**默认不可信**——经度通常对，纬度经常整体漂移。

## 缺图行为

图不存在时 `world_map.gd` 回退到程序化简笔海岸线（`LAND_POLYS`），功能完整、只是丑。
所以这张图是纯美术升级，任何时候删掉都不会让游戏崩。

## 拉图后必做

```
godot --headless --path . --import
```

不 import 看不到新图（`.godot/` 不入库）。
